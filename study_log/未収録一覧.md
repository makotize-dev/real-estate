### 監査の方法（8/5の法令制限監査より精度を上げた）

1. **母集団を一次で取る**：`lawdata` API で全文を取得し、`<MainProvision>`（本則）だけを切り出して**条名＋条見出しを機械抽出**した。取得数＝**宅建業法201条／民法1,173条／借地借家法61条／区分所有法134条／不動産登記法175条**（5本とも `</DataRoot>` まで到達＝末尾切れなし）。
2. **抽出漏れを潰した**：初回の正規表現が**条見出し中のルビタグで切れて条文を落としていた**（民法「意思表示」の節が93条を落として94条始まりになり、代理が20条→19条になった）。タグを剥がす方式に作り直して再取得。**監査で条文を落とすと監査の意味が消える**ので、節ごとの条数を数えて検算した。
3. **ノート側は見出しだけでなく本文を検索**して判定した（鉄則D）。見出しに無くても本文にあるものは「収録済み」に入れている。
4. ※**どの条文が出題対象かの選定は Claude の判断であり、出題実績の統計に基づくものではない**（8/5と同じ限定）。

**この監査で分かった、数え方以外のこと**：
- **業法の未収録は「本体の条文」ではなく「周辺と委任先」に偏っている**。8/2の「業法の失点は読み方」は**本体の条文には当てはまり、周辺には当てはまらない**——問44・45が2問続けて外側で落ちたのは偶然ではない。
- **権利関係は「収録済みの分野は深いが、分野そのものが丸ごと無い」型**。制限行為能力・代理・抵当権・相続は細目まで入っている一方、**債権各論の半分と不登法がゼロ**。ユーザーの「R1でひととおり学習したつもりだったが未習が多い」という実感は、**この分布の偏りが原因**（学習した分野の中は濃いので「やった」感覚が残る）。
- **「消化済み」が浅さを隠す構造**（8/8の35条）は、**31条の3（枝番だけ持っている）**にも同じ形で存在する。

### この監査を置いた理由（8/8のユーザーの申告）

**背景**：8/8に令和2年 問44で**35条の省令の層（規則16条の2・16条の4の3・16条の4の4）と35条3項が丸ごと未収録**と判明した。roadmapのR1「35条（全項目）」枠は7/13に「✅全問正解」で消化済みだったので、**「消化済み」が浅さを隠していた**。

**ユーザーの申告（8/8）**：「R1でひととおり学習したつもりだったが未習がかなり多い。このペースで間に合うのか不安」→ **不安の実体は「あとどれだけあるか分からないこと」**とユーザーが確認。**残量を「あと何項目」に変えるための監査**をここに置いた。→ **上の C. で「優先 約29項目」に確定した**。

**次に同種の監査をするときの手順**（法令が変わっても使える）：`lawdata` API で全文取得 →`<MainProvision>` を切り出し →`<Article>` 単位で `ArticleTitle`／`ArticleCaption` を**タグを剥がしてから**抽出（**ルビタグで正規表現が切れて条文を落とす**のが最大の罠）→節ごとの条数で検算 →ノート側は**見出しでなく本文を検索**して突き合わせる。スクリプトは scratchpad の `index2.ps1`（セッション限り）。
